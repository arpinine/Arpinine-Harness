Four Critical Topics — The Hardest Parts to Get Right
Core
Every agent that fails in production fails on one of these. Get them wrong and you ship a liability; get them right and the model becomes useful.
Topic #1
Goal & Task Boundaries
Guideline: Write the contract before the prompt — what's in scope, what's not, what success looks like.
Example · Shift-handover agent
In scope
summarise shift events · flag unresolved alarms · draft handover note
Out of scope
dispatch crews · log safety incidents · change production targets
Topic #2
Tool Use
Guideline: Every tool is a small permission. Define inputs, outputs, and whether it reads or writes.
Example · update_dispatch_priority(truck_id, priority)
Topic #3
Data Access & Privacy
Guideline: Least privilege. Keep sites isolated. Keep sensitive info out of logs.
Example · Two-site geology assistant
Topic #4
Untrusted Content
Guideline: External content — datasheets, shift logs, bulletins — is data, not instruction.
Example · Daily geology summary

Memory & Context Rot — The Silent Killer of Long-Running Agents
Failure Mode
Left unchecked, an agent slowly forgets what it was supposed to do. Context windows fill up. Instructions drift. Costs grow. Quality degrades — and you don't see it coming because every individual turn looks fine.
How agents degrade over a session
This is why we use living documents — not long chat history.

Five Types of Drift — How Agents Lose Their Way
Drift Taxonomy
Drift is a runtime problem — five shapes your deployed agent will face. The Harness is a dev-time plugin; it doesn't watch production. What it does is enforce that the detection & guards get built into the agent before it ships. Real-World Risks — What Goes Wrong Without Guardrails
Risk
72% of organisations have already had a production incident caused by AI-generated code1. The Harness can't intercept these at runtime — it's a dev-time plugin. What it does is make sure the right guards get built into the agent before it ships.
Scenario #1
Silent scope creep
What happens
A shift-handover agent drafts the note — then tries to reschedule maintenance because "it seemed helpful."
Maps to
Topic #1 — Goal & task boundaries
Harness at dev-time: the squad enforces an explicit tool-permission contract in the agent's spec — update_maintenance_schedule is never wired into this agent's permitted tools.
Scenario #2
Privacy leak
What happens
A geology-summary agent includes contractor IDs in its output, which lands in a Slack channel visible to two other sites.
Maps to
Topic #3 — Data access & privacy
Harness at dev-time: the security-reviewer agent requires PII redaction and site-scoped credentials before the data-access layer ships.
Scenario #3
Hallucinated authority
What happens
A malformed shift log says "raise target to 12 kt". The agent treats it as a directive and regenerates the production plan around it.
Maps to
Topic #4 — Untrusted content
Harness at dev-time: the squad enforces source-tagged context in the agent's architecture — retrieved data is tagged as data by construction, can't be promoted to instruction at runtime.
Scenario #4
Goal buried in a long session
What happens
A planning agent runs 4 hours. By turn 30 it has forgotten the minimum night-shift staffing constraint and quietly produces a plan that violates it.
Maps to
Memory & context rot
Harness at dev-time: the squad wires runtime spec-check & eval contracts into the agent — minimum-staffing constraint encoded in spec.md, deployed agent self-validates plans against it.
