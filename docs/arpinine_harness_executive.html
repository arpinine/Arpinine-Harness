EP 1 — Ad-Hoc

No infrastructure. Pure human discipline. Same errors recur because nothing captures them. Quality is entirely person-dependent.

EP 2 — Contextual

Context injected manually each session. Quality improves — but only because a human remembered to inject it. Remove the human, quality drops.

EP 3 — Formal Planning

Process is defined. But enforcement is still manual. A human must remember to follow the process. Nothing runs automatically. Nothing compounds.

EP 4 — Infrastructure ⚡ The automation threshold

Rules enforce automatically at commit time. Errors generate constraints that fire on every future session. The infrastructure improves — humans confirm, not police.

EP 5 — Self-sustaining Infrastructure

A new engineer gets EP 4 quality from day one — the infrastructure gives it to them. The system no longer depends on any individual's discipline or memory.

Diagnostic: Open your rules file. If it's empty, you have process — not infrastructure. Quality depends entirely on individual discipline. It will not scale.

What Infrastructure-Governed AI Engineering Looks Like
Worked Example
Scenario: A team builds an internal operational assistant — an LLM-powered agent that reads sensor data, queries maintenance records, and recommends equipment interventions. Built with Claude, RAG over operational databases, tool calls to SCADA systems. 3 engineers, 6-week build. AIN 3→4 territory: the product is an agent. Every EP governance failure is also a product failure.
Without infrastructure — what actually happened
EP
No prompt version control

System prompt edited 11 times in 6 weeks. Output schema broke on edit 4 — caught by a user on week 7. No one knew which version was live.

EP
No eval contract — silent degradation

Recommendation accuracy: 91% in demo, 67% in week 5 production. No baseline locked. No alert fired. Operators began ignoring recommendations before anyone noticed.

AIN
No feedback loop — AIN 2 product, AIN 4 ambition

Agent outputs displayed. Operator decisions not captured. Could not learn from outcomes. Closed loop never designed in — impossible to retrofit cheaply.

EP
No security boundary — tool calls unscoped

Agent had write access to maintenance scheduling. A hallucinated tool call rescheduled a preventive maintenance window. Caught manually — by chance.

With infrastructure running — same team, same model
EP
Prompt versioned, baseline locked automatically

Every system prompt edit is a versioned commit. Semantic diff runs automatically. Edit 4 would have blocked deployment — schema change detected before reaching production.

EP
Eval contract alerts at 85% threshold — automatically

Baseline locked at 91% on deploy. Regression fired in week 3 — caught in week 3, not week 7. Operators never lost confidence in the system.

AIN
Feedback loop designed in — AIN 4 from day one

Operator decisions fed back as structured observations. Agent learns from outcomes. Accuracy: 91% at launch → 96% by week 8. Closed loop by architectural intent.

EP
Least-privilege enforced at infrastructure level

Tool scopes declared in plan.md. Write access requires human confirmation gate. Hallucinated calls hit a structural boundary — not a human catching it by chance.
