# ADR-0002: Stable dist/plugins/ dir as local marketplace registration target

## Status
Proposed

## Context
Claude Code's local marketplace registration (`claude plugin marketplace add <path>`) requires a stable directory path. Once registered, that path is stored in the user's Claude config and must remain valid across rebuilds.

We want all generated build artifacts to live under `dist/`, not at the repo root. That includes the assembled plugin used for local marketplace registration, not just the distributable zip.

## Decision
The assembled Claude plugin output is copied to `dist/plugins/arpinine-harness-claude/` after every assemble. This directory is:
- generated by `make assemble IMPLEMENTATION=claude`
- registered through the generated marketplace manifest at `dist/.claude-plugin/marketplace.json`
- ignored by git and recreated locally when needed

The generated Codex marketplace manifest lives at `dist/.agents/plugins/marketplace.json` and likewise points at `dist/plugins/...`.

The `dist/` directory is the single home for both assembled plugin directories and packaged zip artifacts. Marketplace manifests remain checked-in source files, but they point to `dist/plugins/...` rather than a repo-root `plugins/` tree.

## Consequences
- Positive: `make assemble` recreates the registration target deterministically from `src/`.
- Positive: Source of truth stays in `src/`, not in checked-in generated artifacts.
- Positive: All generated output now lives under one directory tree, which simplifies cleanup and reduces confusion about source vs build artifacts.
- Negative: `make clean` removes `dist/`, so anyone using local marketplace registration must re-run `make assemble` before install, validation, or marketplace operations.
- Negative: The local marketplace registration path still disappears on clean; stability comes from deterministic recreation at the same path, not from persistence on disk.

## Alternatives Considered
| Option | Rejected Because |
|--------|-----------------|
| Use `dist/<build-name>/` as registration target | Versioned build paths change per release; marketplace registration should point at a stable assistant-specific path |
| Use `src/arpinine-harness-core/` directly as registration target | Core directory lacks implementation-specific artifacts; not a valid assembled plugin |
| Register from a fixed symlink pointing to `dist/` | Symlinks are fragile across clean cycles and not portable across operating systems |
